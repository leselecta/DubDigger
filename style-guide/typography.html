Typography

Two families.

A self-hosted Helvetica clone for names and headlines, on every platform. IBM Plex Mono, uppercase and letterspaced, for everything structural: labels, counts, roles, meta, controls. There is no third family and no italic anywhere.

The families

Token Stack Job
--font-sans "DubDigger Sans", "Helvetica Neue", Helvetica, Arial, sans-serif Names, headlines, prose. DubDigger Sans is a subset of TeX Gyre Heros, a real Helvetica clone within 0.88% of Helvetica Neue on width, and it is served to every platform rather than only to the ones missing Neue. The trailing system names are a safety net for a failed download, not a second design. Windows used to get Arial and Android Roboto, 6% narrower.
--font-mono "IBM Plex Mono", ui-monospace, monospace Everything structural. Self-hosted from @fontsource/ibm-plex-mono, weights 400, 500 and 600 only, so the deploy touches no third party.

Only 400, 500 and 600 of the mono are downloaded. Asking for any other weight gets a synthesised face. The footer's wordmark line and the site header both use 600, which is why font-semibold is the heaviest mono on the site.

Display scale

Display type is fluid, reading type is fixed. The handoff specifies pixel sizes that are wider than a phone: a 104px "Moritz von Oswald" needs 900px of viewport. So the handoff size is the upper bound of a clamp rather than an absolute, and these degrade instead of overflowing.

--text-hero clamp(2.5rem, 8vw, 6.25rem) -0.04em 0.92 Home page headline only. --text-name with a lower ceiling: its first line is a sentence, and 6.5rem breaks it.

--text-name-label clamp(2.5rem, 9vw, 7.5rem) -0.04em 0.92 The label page name, one step larger than an artist's. A label name is usually shorter, so it can carry the extra size.
--text-stat clamp(2.5rem, 6vw, 4.125rem) -0.03em — The three corpus figures. Always tabular-nums.

Add a new size only if the design has one. Four display tokens and three reading tokens is the whole scale. A one-off text-[2.5rem] is a new size that nothing else will ever match.

Reading scale

Two reading sizes, told apart by the job rather than by the page. They were both 1.1875rem once, which made a standfirst and four paragraphs of explanation read as one undifferentiated block.

Dub Digger is a tool for digging. Dub techno first. Type an artist, and you see who they worked with and which labels they released on. 

<!-- the paragraph directly under a headline -->
class="text-lead text-ink-muted mt-10 max-w-[760px]"

Every record is connected to another. A producer, a mixing engineer, a bassist who turns up on four other records you already enjoy. That web of credits is how crate diggers actually find music, and it all sits in Discogs. It just isn't optimised for digging this way. 

<!-- prose you settle into: a bio, the Info bands -->
class="text-body text-ink-muted max-w-[760px] space-y-5"
Token Value Leading Job
--text-lead 1.1875rem 1.6 A subheading doing a headline's work: it says what the page is before anyone decides to read it. One per page, directly under the h1.
--text-body 1.0625rem 1.6 Bios, label info, the Info page bands, the "no database" notice.
--text-row 1.25rem — The clickable name in every list row. Bold, tracking-[-0.01em], always with link-rule under it.

The line height rides on the token, so never respell it. A paragraph asks for a size and gets the leading that belongs to it. Eleven call sites used to write 1.6 by hand, three of them as leading-relaxed, which is 1.625 and was nobody's decision.

Prose measures are capped. max-w-[720px] for prose and absence rows, max-w-[760px] for the identity block and the labelled bands, max-w-[920px] for a role string wrapping under a name.

The mono scale

Four sizes, all uppercase, all letterspaced. There is no token for these: they are written as Tailwind arbitrary values at the call site, because the tracking changes with the job and a token would fix one pairing for everything. The mono-label utility is the one combination common enough to name.

Counts are tabular-nums, always. A column of figures that shifts width as it counts up, or between rows, reads as noise. It is on the row count, the meta column, the three figures and the stat line.

Numbers are formatted toLocaleString("en-GB"). Never printed raw. The one exception is a year, which is a label rather than a quantity.

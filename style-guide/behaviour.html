Behaviour

Prefer the server.

Then a link, then a script. Tabs, pagination, sort and search are links and a plain GET form carrying state in the URL. Six inline scripts exist, each one because the answer genuinely is not knowable on the server, and a seventh needs the same argument.

The budget

Measured, and the heaviest page is an artist or label at 21,438 bytes
Script Bytes Where Why it cannot be the server
ClientRouter 16,075 every page 76% of the budget, and deliberate: the premise is that a pivot costs one click, so the document is swapped rather than reloaded.
drawer 1,064 every page Buys the two frames <details> does not give you: opening off-canvas, and staying open long enough to slide back. Plus the focus wrap.
contact dialog 961 every page A dialog cannot come from the server. Everything the browser implements is left to the browser, which is why it is smaller than the drawer despite doing more.
scroll hold and active tab 662 every page Where the reader was is not something a server response can carry, and neither is a scroll offset. One script in the layout serving the tab bar, the sort control and "Load more", holding the page's y across a swap and putting the active tab back in view on a row too narrow to show them all.
search suggestions 1,641 every page A keystroke has not been submitted yet. Everything else still is the server: /suggest is a partial returning the rows as markup, so this only fetches, assigns and moves a highlight — no JSON, no templates in the browser.
collapsing bio 1,035 artist, label Whether the text overflows depends on the rendered line count at this viewport.
figures count-up 644 home Whether the band has been scrolled to is not knowable either.

There is no UI framework, and adding one needs an argument. React was here for a week and bought a hamburger menu and a counter for 184 KB, which is the whole case against it. Client behaviour is a <script> tag in the component that needs it, driving the DOM through data- attributes.

A fragment was tried for the scroll hold first, to keep it a link and spend nothing. A fragment can only say "put the tab bar at the top", which still moves the page when you switch from a third of the way down.

The two rules

Scripts must survive a ClientRouter navigation

Do

document.addEventListener(
  "astro:page-load", () => {
    document
      .querySelectorAll("[data-thing]")
      .forEach(setUp);
  },
);

Don't

document
  .querySelectorAll("[data-thing]")
  .forEach(setUp);

// runs once at parse time, then
// silently stops working on the
// second page a visitor opens

The exception is a listener bound to document itself, which the swap does not replace. That is why the scroll hold needs no rebinding, and why it also has to reset anything it left on the <html> element.

Motion is guarded

// all three scripted animations check it
if (matchMedia("(prefers-reduced-motion: reduce)").matches) return;

/* and so does the drawer's stylesheet */
@media (prefers-reduced-motion: reduce) {
  .bar, [data-drawer], [data-scrim] { transition: none; }
}

Reduced motion gets the true state, not a degraded one. The figures show the real numbers, the drawer opens and closes without sliding, the bio opens without animating. Nothing is withheld.

Hooks

The data attributes behaviour is wired through
Attribute On Does
data-hold-scrollTabs, SortBy, LoadMoreKeeps the viewport where it was across the swap. Records the destination too, so a click that never navigates cannot strand a position.
data-tab-rowTabsThe scrolling row. After a swap, and at parse time for a cold deep link, the active tab is scrolled back into view, clear of the scroll hint by its own width.
data-menuthe drawer's <details>Marks it for the slide script.
data-shownsame elementIntent, not state: a details sliding shut is still open. The CSS reads this for the way out.

data-contact-openany mailto: linkIntercepted to open the dialog. Degrades to the real address.
data-contact / -close / -copythe dialogThe card, its × and its clipboard button. data-copied swaps the icon from CSS.
data-collapsible / -clamp / -inner / -fade / -togglebio, label infoMeasured after paint; a short bio renders as a paragraph with nothing to click.
data-suggest / data-suggest-list / data-suggest-option / data-activeSearchFieldThe form carries the minimum character count, so the guard in the browser and the guard in the query are one constant.
data-figures / data-countthe home bandThe real value, handed to the script only when it is going to animate.

Behaviour is wired through data- attributes, never through class names. A class is styling and can be changed by a design decision; a data attribute is a contract with a script.

Three overlays

Drawer (sheet) Contact (modal) Suggestions (combobox popup)

Scroll lockdocumentElement.style.overflowthe browsernone

A sheet is a layer over something you can still see; a modal is the only thing on screen until it is dismissed. Two overlays, two different claims, two different mechanisms. Marking the page inert behind the drawer would hide from a screen reader the thing the design is making a point of keeping in view.

The dropdown is neither. It covers nothing it needs to take focus from, so it takes none: the ARIA 1.2 combobox keeps focus in the input and points aria-activedescendant at the highlighted row. Only that row carries an id, given on highlight and taken back on leaving, because the header and the drawer both render the field and an id has to be unique in a document.

Server-side vocabulary

Two lookup tables sit in web/src/lib/ rather than in the database, deliberately: both are editorial, both will be revised, and nothing about them is baked into the SQLite file. A wrong name is a code fix rather than a re-ingest.

File Holds Rule
lib/roles.ts 61 entries, read by creditLine() Drops the bracketed qualifier, collapses the variants Discogs spells differently, states each role once. The table's order is the display order: what someone made, then how it was cut, then what they played, then the sleeve and the office. An unrecognised role keeps its raw wording and sorts last — never dropped, never guessed at. Coverage is 97.4% of 4,429,673 credit occurrences.
lib/scene.ts the canon: 19 artists, 52 labels What the Core pages rank on. Aliases inherit their artist's standing above a floor of 10 releases; groups and members never do, because an alias is identity and a band is association.
lib/view.ts PAGE_SIZE, LIST_SORTS, listSort(), listHref(), sortList(), percent(), years() 40 rows before "Load more", clamped to 1,000. A share floors at "<1%" rather than rounding to zero, because "0% of output" next to a count of 6 reads as a broken figure.
lib/seo.ts canonicalPath(), countLine() The canonical drops the query string. The description is built from the tab counts and drops what the corpus does not have.

Ingest stores the dump's string verbatim; the app names it. That split is the point, and it is why the vocabulary can change without a re-derive. A merge is a claim, so only merge what means the same work.
